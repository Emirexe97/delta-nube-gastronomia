# Corrección 0.1.34 — bloqueo al guardar el PIN de un usuario

El usuario informó que el programa se tildaba al asignar un PIN nuevo después de actualizar a 0.1.33. Se reprodujo el bloqueo con un perfil temporal: una actualización de PIN detuvo los temporizadores del proceso principal durante 3.783 ms.

## Cambio

- El IPC de alta, edición y eliminación de usuarios, alta de repartidores y configuración inicial del administrador prepara las comprobaciones bcrypt de forma asíncrona. Las comprobaciones costosas ya no monopolizan el hilo principal durante toda la operación.
- Antes de guardar se revalida el conjunto de usuarios activos y sus hashes. Autorización, permisos vigentes, unicidad y auditoría siguen en una transacción síncrona; ninguna transacción permanece abierta durante los awaits. Cambios concurrentes en credenciales invalidan el intento. Los resultados temporales se limpian al terminar o fallar.
- Se mantiene bcrypt con costo 12, el rechazo de PINs ambiguos heredados y de duplicados. No cambia el esquema SQLite ni se migra o restablece ningún PIN al instalar.
- La interfaz de Usuarios muestra Creando/Guardando y evita doble envío o cierre accidental durante el guardado; conserva el borrador ante un error.

## Verificación

- Typecheck y build de 0.1.34: 11/11 paquetes aprobados en cada caso.
- SQLite: 11 pruebas focalizadas aprobadas (configuración inicial, autorizaciones y nuevo trabajo de PIN). Incluye latido del event loop sin transacción abierta, costo bcrypt, PIN incorrecto/duplicado/ambiguo, revocación de permisos durante la preparación, cambio desde otra conexión y dos altas concurrentes con el mismo PIN.
- Tres pruebas de admisión de operaciones/actualizaciones aprobadas.
- Seis recorridos Electron aprobados: PIN inicial, repartidores, respuesta del proceso principal durante la actualización y guardado real desde Usuarios con rechazo de duplicados sin perder el borrador. La misma prueba que fallaba a 3.783 ms pasó con el máximo bloqueo por debajo de 500 ms.
- Paquete real Windows 0.1.34: main y renderer idénticos a la compilación probada; corrección presente en ASAR. Apertura sobre copia consistente del perfil real, integridad y claves foráneas correctas, todas las filas, precios y caja conservados (esquema 49→49). Perfil de prueba sin licencia: UNACTIVATED, sin activación ni cambios en identidad real.
- Evidencia privada ignorada: `apps/desktop-shell/release/qa-pin-freeze/` y `apps/desktop-shell/release/qa-0.1.34/`.
